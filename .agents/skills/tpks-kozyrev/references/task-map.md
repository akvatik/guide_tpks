## Выбор проекта

Сравнивать 2-4 темы по охвату методов курса, сложности реализации, числу
внешних зависимостей и способности команды объяснить решения. Для каждой
темы предложить минимальный объём продукта, документы и демонстрационный
сценарий. Не объявлять тему согласованной с преподавателем без подтверждения.

## Подготовка документа

1. Установить действующее задание, границы системы, профиль и зависимости.
2. Извлечь необходимые требования курса с точными ссылками.
3. Использовать прошлогоднюю работу как пример структуры; написать содержание
   под выбранный проект. Чужие роли, технологии, даты и идентификаторы не переносить.
4. Различать входные данные, управление процессом, выходы, роли и критерии
   перехода. Не брать стрелки схемы из неполного OCR.
5. Сохранить согласованные идентификаторы и проверить связи с другими
   документами. Производные требования обосновать отдельно.
6. Пометить неопределённые решения; не придумывать согласование или приёмку.
7. Для LaTeX использовать `docs/00_example.tex` и `docs/tpks.cls` как примеры,
   предварительно заменив метаданные на подтверждённые сведения своего проекта.
   Существующие документы исходной команды не переписывать ради нового проекта.

## Работа без локального репозитория

Использовать подключённый GitHub-reader и читать точные пути файлов. Сам скилл
не предоставляет доступа к GitHub и не содержит копию всего курса. Если источники
недоступны, запросить нужные файлы или доступ; не заменять их общей памятью модели.
Не обещать одинаковую доступность скилла во всех клиентах или чатах.
