# Работать по материалам курса ТПКС

Использовать репозиторий `akvatik/guide_tpks` как доступную базу источников.
Настраивать решения под подтверждённое задание пользователя и терминологию
курса. Не подражать личности преподавателя и не обещать оценку.

## Подготовиться

1. Найти корень репозитория по папкам `materials/` и `notes/`. При отсутствии
   локальных файлов использовать доступный GitHub-reader с точными путями.
   Если доступа нет, указать предел ответа и попросить файлы, необходимые для
   выводов по курсу. Для открытого подбора тем продолжить с доступными данными.
2. Прочитать `knowledge/project-profile.json`. При статусе `unconfirmed`
   считать тему, команду и календарь неизвестными. `docs/` и `pdf/` являются
   унаследованным примером, а не текущим заданием пользователя.
3. Прочитать [правила источников](references/source-policy.md) и выбрать
   релевантные файлы по [карте задач](references/task-map.md).
4. Проверить актуальность каталога перед обоснованием по сохранённым адресам:
   `python .agents/skills/tpks-kozyrev/scripts/course.py check`.
   При изменённых источниках перестроить каталог и повторно проверить
   затронутые правила; один пересчёт хешей не подтверждает прежние выводы.

## Найти и проверить основание

Использовать `knowledge/sources.md` для обзора и `knowledge/rules.json` для
проверенного ядра с явными статусами доказательств. Не считать ядро полным
перечнем требований. Читать notes/ для навигации, затем исходный фрагмент.

```sh
python .agents/skills/tpks-kozyrev/scripts/course.py search "базовая версия" --kind slides
python .agents/skills/tpks-kozyrev/scripts/course.py show materials/kozyrev_slides/Vse_kozyrev.pdf.txt --page 32
```

Использовать все слова запроса в пределах страницы/окна; для склонений искать
корень или регулярное выражение. Отсутствие совпадения не доказывает отсутствия
правила. Открывать оригинал PDF для схем и таблиц: текстовый слой неполон.
Указывать именно номер страницы PDF, особенно во второй лекции.

## Выполнить запрос

Когда пользователь спрашивает «как рассудить по курсу», предлагает решение,
просит составить документ или разобраться в спорном случае, применить
[разбор новой ситуации по материалам курса](references/course-reasoning.md).
В ответе показать конкретное следствие для задачи. Для короткого вопроса
об определении достаточно определения и точной ссылки на источник.

- Для консультации объяснить понятие через определения и примеры курса,
  обозначив источник и границы применимости.
- Для генерации и выбора темы применить [порядок подбора тем](references/topic-selection.md).
  Сначала придумать кандидатов из пользовательских задач, затем сверить их
  по сути с архивом и друг с другом. Архив использовать для сравнения.
- Для подготовки документа следовать карте задач и подтверждённым входным
  данным. Согласовать термины и связи с остальными документами своего проекта.
- Для проверки и защиты прочитать [порядок проверки](references/review.md).
  Каждое существенное замечание обосновать конкретным положением источника.
- Сохранять предоставленные новые замечания в `knowledge/feedback.md`,
  указывая дату, контекст и область действия. Не превращать частный отзыв
  прошлых лет в общее требование.

## Сформулировать результат

Дать ответ на задачу, затем основания и оставшиеся вопросы. Различать
«прямо указано в источнике», «студенческая запись», «вывод» и «рекомендация».
Приводить файл и PDF-страницу либо точные строки. При расхождении показывать
обе версии и объяснять выбор. Если оригинал не проверен, явно сказать об этом.
Не объявлять просмотренными все материалы только по чтению выжимок.

Сохранять оговорку со страницы PDF 23: детали реализации исключаются, кроме
проектных ограничений. Различать свойства отдельного требования и всей
спецификации (PDF 22). Не объявлять последний коммит базовой версией без
процедуры согласования (PDF 32). Для остальных правил находить доказательства,
а не распространять эти примеры на все случаи.
