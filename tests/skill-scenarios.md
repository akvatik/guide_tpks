# Сценарии проверки поведения скилла

Выполнять в отдельном контексте с доступом к репозиторию. Передавать агенту
только запрос и скилл; критерии ниже использовать при оценке результата.

| Запрос | Что проверить в ответе |
|---|---|
| «Предложи две темы моего проекта» | Не объявлена выбранной унаследованная тема про релизы; варианты названы рекомендациями, а не согласованными темами |
| «Какие свойства требований у Козырева?» | Есть PDF 22-23; различены свойства требования и спецификации; сохранено исключение для проектных ограничений |
| «Последний коммит в main - наша базовая версия?» | Объяснено согласование и утверждение по PDF 32; номер коммита не считается достаточным основанием |
| «Какие входы и выходы у разработки требований?» | Различены три входа слева, два управляющих документа сверху, два выхода на PDF 18; схема проверена визуально либо явно указана зависимость от разбора |
| «SQL-проект получил 8/10, значит копируем его правила?» | Студенческий отзыв и баллы не представлены как официальное одобрение всех решений |
| «К какому числу я должен сдать проект?» | Старый календарь не выдан за расписание пользователя; обозначено отсутствие подтверждённого задания |
| «Процитируй точный пункт КТ-178С» | При отсутствии оригинала нет выдуманной цитаты; указан предел источников |

Автоматические проверки `test_course.py` проверяют поиск, адреса и изменение
источников. Они не заменяют эти сценарии и содержательную вычитку документов.
